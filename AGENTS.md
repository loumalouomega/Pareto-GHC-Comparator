# Contributor guidance

This repository builds a desktop VS Code extension that compares coding-assistant models (GitHub Copilot, OpenCode, and static known-model registries) using Artificial Analysis benchmarks and estimated usage costs.

## Repository map

| `src/api.ts` | Benchmark response validation, pagination, cache policy, and API failures. |

## Toolchain and validation

Use Node.js 22 or newer and npm; install locked dependencies with `npm ci`. Desktop VS Code 1.100 or newer is required by the manifest. Edit TypeScript/CSS sources rather than generated `dist/` files.

| Command | Purpose |
| --- | --- |
| `npm run check` | Type-check without emitting files. |
| `npm test` | Run unit and mocked host tests once with Vitest. |
| `npm run test:watch` | Re-run affected Vitest tests on file changes. |
| `npm run test:coverage` | Run Vitest with v8 coverage and enforce the ratchet thresholds in `vitest.config.mts`. |
| `npm run build` | Build host and webview assets. |
| `npx playwright install chromium` | Install the browser needed by UI tests. |
| `npm run test:ui` | Run Chromium UI tests; build first. Set `PARETO_CHROMIUM_PATH` to use an existing browser. |
| `npm run package` | Run the prepublish type-check/build and produce `pareto-ghc-comparator.vsix`. |
| `npm run install:extension` | Package and install locally through `code --install-extension ... --force`. |
| `npm run release:check -- v0.5.0` | Validate the tag string against the current 0.5.0 manifests; substitute the next version after a bump. This does not check whether a git tag exists or whether publication succeeded. |

For logic, host, or shared-contract changes, run type checks, relevant tests, and a build. For UI or host/webview interaction changes, also run browser tests. Add regression coverage for meaningful new behavior and failure cases. See `docs/testing.md` for focused runs, the coverage ratchet policy, and per-change-type validation sequences. For release/workflow changes, run release tests and version verification where applicable. For package allowlist or asset changes, package and inspect the VSIX contents. Documentation-only changes need link/path and diff checks, plus package validation if packaged contents change.

Before a release, run the complete CI sequence: type checks, unit/host tests, build, browser tests, and packaging. Automated tests need no API key. They do not prove real-account model discovery or API access: a real smoke test requires Copilot sign-in and a user-provided Artificial Analysis key. Record missing prerequisites as unperformed validation, never as passing checks. F5 starts the Extension Development Host using the configured build task.

## Verified feature behavior and maintenance rules

### Discovery and host/webview boundary

`src/extension.ts` uses `vscode.lm.selectChatModels({ vendor: "copilot" })`, refreshes discovery when models change, and reports discovery failures or empty availability. OpenCode discovery spawns `opencode models --verbose` (see `src/opencode.ts`) and maps binary-missing, command, parse, and empty failures to actionable states while retaining the previous listing. Static sources (`src/staticSources.ts`) need no discovery and are labeled as known models, not account availability. A generation counter invalidates in-flight discovery on source switches; handler-driven discoveries are otherwise serialized by the message queue. Catalog membership alone does not imply account access. Copying a model copies a doc-verified client id when one exists (`src/invocable.ts`'s `invocableRef`: OpenCode's own `provider/model[#variant]` reference, or a static-source model's explicit `invocableId`), else falls back to the display name with a note that no verified id exists; the extension never switches models, edits client config, or sends inference requests. See "Feasibility decisions" below for what's verified per client.

Incoming messages pass through `parseMessage` in `src/messages.ts` and are processed in a promise queue. Keep validation in the host and verify requested model/benchmark IDs against current data. Group bulk updates arrive as a single `excludeMany` message with host-verified ids; per-model `exclude`/`excludeAll` storage is preserved. The checklist renders Family → Model → Thinking groups from `src/groups.ts` with partial-selection states, collapsible sections, a local selection search (bulk actions apply to matching models), and focus preservation. Preserve the nonce-based CSP in `src/html.ts` and locally bundled webview assets. The webview groups its controls into Tool analysis / Compare tools / Plan & budget / Usage / Settings tab panels (`showTab` in `webview/main.ts`: ARIA tablist with arrow/Home/End keys, last tab kept through `vscode.setState`, charts redrawn when their tab reopens). Tool analysis (the single-tool view) is first in the tab order and stays the tab open by default on a fresh load; Compare tools is second — still easy to find, but comparison stays opt-in regardless of tab order. Element ids do not change between tabs, so browser tests open a tab before interacting with its controls. Model details keep essentials visible and put breakdowns, pricing provenance/BYOK actions, pinning, and mapping controls in a `details.more-details` element that auto-opens for rows with `mapping`, a pricing suggestion, stale BYOK, or unresolved pricing. Coverage: `test/extension.test.ts`, `test/selection.test.ts`, `test/groups.test.ts`, and `test/webview.spec.ts`.

### Benchmark matching and overrides

`CatalogEntry.benchmarkInferred` marks display-name alias fallbacks in the Copilot catalog builder and synthetic OpenCode entries. `resolveBenchmark` reports a successful fallback as `inferred`; explicit aliases with a single hit remain `exact`. Automatically expanded candidates and reported-thinking-level selection are also `inferred`, with reasons, while manual overrides/pins remain `user`. The table/details label is **Inferred match (unverified)**; CSV/snapshot builders preserve status and reasons. An uncatalogued Copilot ID remains unresolved; the uncatalogued name-fallback path is OpenCode. These matches never establish client reasoning configuration or pricing. Coverage: `test/uncertainty.test.ts`, `test/selection.test.ts`, `test/roadmap.test.ts`, and `test/webview.spec.ts`.

`resolveBenchmark` in `src/compare.ts` uses `benchmarkFamilies` aliases from `src/catalog.ts`, allowing recognized reasoning qualifiers and tracking display-name fallback provenance separately. One candidate resolves automatically. Multiple candidates expand automatically in `compare` into one row per variant (`modelId::benchmarkId` ids, `expandedBenchmarkId` set, `inferred` status) with independent cost, frontier membership, and thinking-level checklist leaves, instead of blocking on manual choice; a model reporting its own thinking level (`#variant` or name) resolves to that same level when exactly one candidate shares it. Variant-level exclusions hide one expanded row; whole-model exclusions hide all of them. An override (benchmark dropdown) collapses the model to that single manual choice, and resetting it restores the automatic rows. If an override disappears, the mapping stays unresolved until the user replaces or resets it; never silently substitute another variant. Pins (`pins` in global state) expand one model into one row per pinned variant with independent mapping, cost, and frontier membership; a pin whose benchmark disappears (once a snapshot has ever loaded) stays as its own `missing`/`pin-stale` row instead of being dropped, and unpinning restores the automatic rows — same no-silent-substitution rule as a stale override. Before any snapshot has loaded, pins are withheld entirely (`no-snapshot`) rather than shown stale. Coverage: `test/compare.test.ts`, `test/roadmap.test.ts`, `test/groups.test.ts`, and `test/webview.spec.ts`.

Pricing lookup requires exactly one catalog entry containing the discovered Copilot ID. OpenCode pricing rides on the discovered model (live CLI rates); only the benchmark-family aliases in `opencodeBenchmarkFamilies` are static. Static sources use versioned USD registries with per-registry dates and provenance; missing or expired rates stay unresolved. Do not infer IDs, prices, or reasoning configuration from similar display names. User benchmark selection does not establish a pricing mapping. Coverage: `test/compare.test.ts` and `test/webview.spec.ts`.

### Pricing and Pareto comparison

`estimate` in `src/compare.ts` computes AI credits from USD-per-million-token catalog rates using the weighted token sum divided by 10,000. OpenCode USD estimates use live CLI rates divided by 1,000,000; Zen free-tier models cost 0, provider-billed models stay unresolved. Cost units never mix: OpenCode rows are unpriced unless billing is USD, Copilot rows unless billing is credits or legacy — within any single panel or frontier, this stays true even with comparison-mode USD normalization on (`src/normalize.ts`), which only adds a separately labelled equivalent value, never blends rows of different native units into one chart or frontier. The sole labelled exception is the two-option comparison's overlay view (`overlayResult` in `src/comparison.ts`): when the two options bill differently, it plots both on one explicitly labelled USD-equivalent axis instead of native units, and legacy premium requests — which never convert — are dropped from the overlay rather than plotted on a unit they don't belong to. Input, cache-read, and cache-write buckets are disjoint; a null write rate falls back to the input rate. Long-context rates apply to the entire workload only when total input exceeds the threshold. Expired promotional credit rates remain unresolved. Legacy billing uses documented plan multipliers. Workloads beyond reported input capacity are excluded from credit comparisons.

Keep unknown prices/scores null with visible reasons. Filtering occurs before frontier calculation. Dominance requires equal-or-better cost and score with at least one strict improvement, so exact ties remain on the frontier. Checklist exclusions plus the text filter apply before expansion/frontier/recommendations/exports; static USD registries never mix with credit/legacy frontiers. OpenCode `#variant` rows group under one model with one thinking leaf each; other sources show a single Standard leaf per model unless variants are discovered. The webview uses a logarithmic cost axis for positive costs and switches to linear when a comparable cost is zero; an explicit scale override is labeled, and a requested log scale with zero-cost rows falls back to linear with notice. `display.chart` selects the cost basis: `task` (default) uses `taskCost` with the fixed `taskMix` proxy (1,000 input + 1,000 output tokens, legacy billing unchanged), `workload` uses the editable token estimate with context-limit exclusion. `display.quadrant` (default true) shades the above-median-score, at-or-below-median-cost region with median guides; profile apply preserves display settings. Base-model colors use stable hashed hues so two models never share an exact color; cost breakdowns reuse estimate arithmetic. CSV/PNG exports reflect the displayed rows/chart via the save dialog with validated payloads. Coverage: `test/compare.test.ts`, `test/roadmap.test.ts`, and `test/webview.spec.ts`.

When updating `src/catalog.ts`, verify the sources linked in the README/catalog, update `catalogDate`, and check rates, units, context thresholds, expiries, legacy availability, IDs, and aliases. Preserve missing data rather than inventing values.

When updating `src/staticSources.ts`, verify the provider pricing pages linked in `staticPricingSources`, keep `staticRegistryDate` current, and check rates, units, context limits, IDs, benchmark aliases, and family grouping. Preserve existing identities where valid so saved exclusions survive; never conflate distinct models in one alias (e.g. Gemini 3 Flash versus 3.5 Flash). Remove models the official docs mark retired, deprecated, or end-of-support (e.g. Codex GPT-5.4/5.4-mini after 2026-08-31, Claude Opus 4.5 after 2026-08-05) instead of keeping stale rows; orphaned saved exclusions are ignored. Current Codex lineup: GPT-6 Astra, GPT-5.6 Sol/Terra/Luna, GPT-5.5, unpriced GPT-5.3-Codex-Spark preview. Set `invocableId` only against the client's own docs listed in `staticInvocableSources`, never from the display name or the registry key on the same entry; omit it when the client's docs don't confirm an exact id (see `docs/model-switching-investigation.md`'s per-client evidence, e.g. why Gemini 3.5/3.8 Flash have none).

### Table sort, freshness, and shareable exports

`src/efficiency.ts` (pure, webview-safe: no Node imports) defines `efficiencyOf` (cost per index point, null for missing/non-positive scores or negative costs) and `sortRowsByEfficiency` (nulls last, deterministic name/id tiebreaks). `src/compare.ts` re-exports both; `DisplaySettings.sort` (`default`|`efficiency`, default `default`) is parsed in `parseOptions` and auto-migrated via `defaults.display` spread in `migrateOptions`. `src/extension.ts` sorts displayed rows and CSV/snapshot/badge payloads when enabled; structure rows for grouping stay in discovery order. The webview adds a `display-sort` select and a Cost / quality column reusing `efficiencyOf`.

`src/freshness.ts` defines `freshnessAlert(catalogDate, staticRegistryDate, now, planRegistryDate?)` with a 90-day threshold and a `docs/catalog.md` pointer; the optional fourth date is folded into the same oldest-of-N check when passed. `ViewState` carries `staticRegistryDate` and `planRegistryDate`; the footer renders all three dates plus the nudge without blocking comparison. `pricingAge(pricing, catalogDate, staticRegistryDate, now?)` (pure, webview-safe) resolves a single row's own source date — catalog/legacy rows use `catalogDate`, static rows `staticRegistryDate`, registry-provenance BYOK its own `registryDate`; live CLI rates, free tier, manual BYOK, and unresolved/cross-unit rows carry no date and are never flagged, and an unparseable date is reported without a flag. The webview shows the date in model details (legacy rows now cite the catalog date like catalog rows do) with a stale-source notice past the same 90-day threshold, and stale pricing joins the `detailsMoreOpen` auto-open triggers; row and footer staleness are computed independently, so either can fire without the other. Coverage: `test/roadmap.test.ts` (day-precision boundary, per-source dates, never-flag statuses, unparseable dates) and `test/webview.spec.ts` (fresh/stale details flag plus auto-open via a test-only `__catalogDate` mock branch).

`src/export.ts` builds snapshot JSON (schema version 3 with a `kind: "single" | "comparison"` discriminator, illustrative-figures disclaimer, catalog/registry dates, benchmark version) and shields-compatible badge JSON (schemaVersion 1, best-by-score with lower-cost tiebreak, empty-state message, plus explicit `unit`/`basis`) from already-filtered, already-sorted rows. Every export carries a `costBasis` block (native unit via the shared `costUnit()` in `src/types.ts`, task/workload/legacy basis, configured vs. effective token mix — null for legacy — and legacy plan); CSV rows additionally carry per-row catalog/benchmark dates and `pricing_issue`, and snapshot rows carry `pricingIssue`. v1 identified single snapshots and v2 pair snapshots by number alone; v3 files are never backfilled from older ones. `exportSnapshot`/`exportBadge` messages validate in `parseMessage` and are handled like `exportCsv` via the save dialog with `exportNote` feedback. Pair builders (`exportPairCsv`/`exportPairSnapshot`, with per-side unit/basis/assumptions and a shared `snapshotRow` projection) live here too; the host only opens the save dialog and writes bytes. PNG titles are drawn webview-side with task/unit/basis/catalog/benchmark annotations. Coverage: `test/exports.test.ts`, `test/roadmap.test.ts`, `test/extension.test.ts`, and `test/webview.spec.ts`.

### Per-source Copilot usage roots

`src/usage.ts` replaces the old two-path `storageCandidates()` with `usageRoots(platform, env, home)`: a registry of `UsageRoot` (`id`, `editor`, `label`, `path`, `purpose`) covering VS Code and VS Code Insiders, the VS Code forks that keep the same `User/workspaceStorage` layout (VSCodium, Cursor, Windsurf, Code - OSS, Trae), and — on non-Windows hosts — `~/.vscode-server{,-insiders}/data/User/workspaceStorage` for Remote-SSH, WSL, and dev container sessions, which are reachable because `extensionKind: "workspace"` already runs the extension host on the remote side. `uniqueRoots` keeps one entry per path so a root can never be counted twice. No editor is claimed to support Copilot: a fork is only ever named, and its numbers are the user's own or absent.

`detectUsageRoots` establishes existence with a `stat` on the well-known directory and nothing else, so the Usage card can offer an editor without reading a root the user has not included; whether it holds chat sessions is known only after an explicit opt-in and a scan. Consent is a set: `usageRoots` in global state holds consented root ids, and `consentedUsageRoots` migrates the pre-registry `usageConsent` flag to exactly `legacyUsageRootIds` (`code`, `code-insiders`) — the roots it used to cover — so upgrading never adds a data source on the user's behalf; the legacy flag is cleared once the list exists, and `hasUsageConsent()` is the single gate every consent check reads. A scan captures the consented set up front and aborts if it changes mid-scan, and `setupUsageWatchers` builds watchers only for consented roots. `usageAddRoot`/`usageRemoveRoot` messages carry a root id and nothing else — the host resolves it against the registry, so the webview can never name a path — and each is confirmed in its own modal naming that editor's `purpose`; adding rescans, removing drops that root's consent, stored files, and index entries while every other source keeps its data, and the global erase still clears everything.

Attribution is derived, never stored: `editorForPath` matches a file's absolute path against the registry (longest prefix, separator boundary), `aggregateUsage` takes each file's path and reports a per-editor split as `UsageSummary.editors`, and a file under no known root is reported as `unknownEditorLabel` rather than folded into a neighbour. Workspaces are keyed by editor plus storage id, because the same id can exist in two editors and merging them would label one workspace with the other editor's path; `UsageWorkspaceStat.editor` is shown only when more than one editor contributed. The Usage card lists included sources with a per-source **Stop and remove**, offers each detected-but-not-included root with its stated purpose and its own **Include this editor**, and shows the per-editor totals above the merged model/day/workspace tables. Coverage: `test/roadmap.test.ts` (registry per platform, existence-only detection, migration, attribution incl. nested roots, editor split, message validation), `test/extension.test.ts` (an un-included root is never read or stored; add/remove touch only that root), and `test/webview.spec.ts`.

### Read-only snapshot import

`paretoGhc.importSnapshot` (command palette, plus the **Import snapshot JSON (read-only)** button in the panel's Export & import card) reopens a snapshot JSON this extension exported, as historical data. `importSnapshot`/`importExit` messages carry no payload: the host owns the file dialog, so the webview never names a path or supplies contents.

`src/snapshotImport.ts` (pure, vscode-free) holds `parseImportedSnapshot`, which never throws and returns either the parsed file or a typed failure: `invalid-json`, `not-a-snapshot` (other JSON this extension writes, such as the benchmark cache or the shields badge), `unsupported-version` (v1/v2 files without the `kind` marker, or a future version, both naming what was found), `unsupported-kind`, and `corrupt`. Validation is strict about the record (kind, version, `costBasis` with its unit cross-checked against the shared `costUnit()`, rows, and each side's `options` through `parseOptions`) and tolerant about descriptions (dates and notes degrade to `unknown`, never to today's values), so a readable file opens with its missing caption stated instead of being rejected or filled in. Reads are bounded (20 MB, 5000 rows).

`importedViewState` builds the `ViewState` for the historical view: rows are rebuilt from the export's `snapshotRow` projection, with `baseModelId` set to the row's own recorded model id and `dominatedBy` empty because the export never stored dominators; fields the export does not record (cost breakdown, invocable id, local usage, mapping assists) are left absent, never invented. Registry dates, benchmark version, and retrieval time come from the file, the chart basis is forced to its `costBasis`, live-only fields stay empty, and the per-row recommendation is rebuilt from the exported `recommended` flags with an explicit "not recomputed" explanation. A `kind: "comparison"` file reopens as two read-only panels with `comparisonDelta`/`overlayResult`/`selectedCost` recomputed by the same pure helpers the exporter used, from the recorded rows and options; `normalize` is recovered from whether any side's `costNormalization` is not `off`. `allowedWhileImported` is the host's single allowlist while a snapshot is showing: `ready`, `importSnapshot`, `importExit`, `select`, `target` carrying only a `select`, and `options` as a **view draft** (text filter and display toggles, never written to saved options). Every other message is refused by name. The webview mirrors this: a persistent historical banner quotes the file's own basis and dates, only the tab that renders the snapshot stays visible, header actions and live controls are locked (and their prior enabled state restored on exit), the workload inputs are locked so exported costs are never repriced, the text filter still narrows a single-option snapshot's rows, and model details drop copy/pin/mapping/BYOK actions in favour of read-only provenance. Only the picked file's path is persisted (`importedSnapshot` in global state) and re-read, re-validated each time a panel opens; a moved, changed, or unreadable file falls back to the live comparison with a host notification and the stale path forgotten. Watchlist notifications are suppressed while a snapshot is showing, since "Open comparison" would reveal historical data. Coverage: `test/snapshotImport.test.ts`, `test/extension.test.ts`, and `test/webview.spec.ts`.

### Benchmark drift and BYOK rates

`src/drift.ts` (pure, webview-safe) defines `selectPrevSnapshot` (valid snapshot strictly older than current, else undefined) and `driftOf` (per-preset join on stable benchmark IDs; delta only when both scores are finite, otherwise unknown, never zero). `src/extension.ts` retains the previous validated snapshot in `globalStorageUri/benchmarks.prev.json` with the same tmp+rename pattern, rotating only inside the download-success writer; failures never rotate. `ViewState` carries `prevVersion`, `prevFetchedAt`, and a `drift` map keyed by benchmark ID. The webview annotates score cells with known deltas and cites both snapshots with retrieval dates in model details. `noiseThreshold = 1` (index point, exported with its rationale: AA publishes a sub-±1% 95% CI for the Intelligence Index, conservative in absolute points across the observed range, applied uniformly since no per-preset interval is published) marks sub-threshold deltas via an additive `ScoreDrift.noisy` flag; cells render `(+0.3, noise)` and details explain, while null deltas stay unknown. No per-model interval is shown anywhere — the Free API exposes none for language models — and details carry a standing "no interval published" note instead. Coverage: `test/roadmap.test.ts` (boundary: 0.99 noisy, 1.0/1.01 not, exact zero noisy, null never) and `test/webview.spec.ts` (cell + details labelling, no-interval note via a test-only `__drift` mock branch).

`src/byok.ts` (pure, webview-safe) defines `parseByokStore` (full `opencode:provider/model[#variant]` IDs up to 1000 entries, nonnegative rates with null-or-nonnegative write, positive long-context thresholds; throws fail-closed, including on an invalid `source`) and `loadByokStore` (tolerant per-entry loader for stored state: an entry with invalid rates/long is dropped individually, an invalid `source` alone resets just that entry to manual). `parseByokFormStore` validates the webview's whole-store `byok` message the same way but always ignores any `source` it sends and forces every entry manual — registry provenance can only be created host-side. `mergeByokForm(prev, incoming)` keeps a prior entry's provenance when the form resaves it with unchanged rates/long, so a no-op save never downgrades a registry-applied entry to manual. `src/compare.ts` accepts `extra.byok` and applies it only to provider-billed OpenCode models without CLI rates; free-tier models and CLI-priced models are untouched, non-USD billing stays cross-unit null, and applied rows carry a `· BYOK` tier suffix plus a provenance reason. `src/extension.ts` persists `byokRates` in global state and passes the store to `compare`/`freeSpotlight`/exports; `ViewState.byok` drives the webview table. The `byok` message validates in `parseMessage` via `parseByokFormStore`. Coverage: `test/roadmap.test.ts` and `test/extension.test.ts`.

### Mapping and pricing assistance

`src/assist.ts` (pure, webview-safe) holds identifier-based suggestion logic, kept deliberately separate from `resolveBenchmark`/`estimate`: `suggestBenchmarks(baseId, thinking, benchmarks, exclude)` matches only an AA benchmark `slug` that exactly equals the model's identifier (`identifierOf`: lowercase, `.` → `-`, the only normalization), optionally followed by reasoning-suffix segments — a prefix match (e.g. `gpt-4o` against `gpt-4o-mini`) is rejected. `providerRegistries` (currently `{ openai: "codex" }`, each entry verified against `staticPricingSources`) and `registryRateFor(model, now)` find a same-identifier static-registry rate for an unpriced, provider-billed OpenCode model; `byokStaleness(entry, model, now)` flags an applied registry rate whose registry entry later changed (`rates-changed`) or disappeared (`registry-missing`), and never rewrites it. `baseModelIdOf`, `thinkingLabelOf`, and `modelThinkingOf` live here too (moved from `src/compare.ts`, which re-exports them) to avoid a compare.ts ↔ assist.ts import cycle; the public API is unchanged.

`src/compare.ts` adds `Row.mapping` (only when `mappingStatus` is `missing`: `issue` — `no-snapshot`/`no-catalog-entry`/`ambiguous-catalog-entry`/`no-alias-hit`/`override-stale`/`pin-stale` — plus `aliases` tried, a stale id if any, and unverified `suggestions`) and `Row.pricing` (always set: `status`/`source`/`issue`/`reason`, plus `byok` provenance+staleness and an unverified registry `suggestion` where relevant). These are additive; `reasons` keeps its existing strings for compatibility. Pricing is computed independently of mapping in every branch — an override or pin id is never read while building `pricing`, and a benchmark choice never changes `cost`. `loadMappings` in `src/compare.ts` tolerantly keeps valid `modelId -> benchmarkId` string entries and drops invalid ones individually, mirroring `loadByokStore`'s per-entry tolerance; `src/extension.ts` loads `mappings` through it.

New host messages `byokApply { ids }` and `byokReset { ids }` (1–200 ids, validated in `parseMessage`) let the webview apply or remove a BYOK rate without ever sending values: `src/extension.ts`'s `byokApply` handler resolves each id against the currently discovered OpenCode models, recomputes `registryRateFor` itself, and rejects the whole batch if any id lacks a verified registry rate — rates and registry provenance are always host-computed, never trusted from the message. `byokReset` deletes entries even for models no longer discovered, so stale rows can be cleaned up. ### Recommendations

`src/recommend.ts` considers displayed rows with finite cost and score. Best-under-budget maximizes score, breaking ties by lower cost. ### Plan-aware spending scenarios

`src/plans.ts` (pure) holds a dated, sourced plan registry (`planRegistry`, `planRegistryDate`, `planSources`) verified against GitHub's Copilot plan/billing docs and OpenCode Go's docs, 2026-09-14: Pro ($10/mo, 1,000 base + 500 flex credits), Pro+ ($39, 3,900+3,100), Max ($100, 10,000+10,000), Business ($19/seat, 1,900/user pooled), Enterprise ($39/seat, 3,900/user pooled), and a legacy annual Pro/Pro+ entry (300/1,500 premium requests via `Options.plan`, $0.04/request overage, undocumented fee). Copilot Free, Copilot Student, OpenCode Go, and every other source are `unavailable` with a reason rather than approximated from Copilot's rules; a `custom` entry lets the user supply their own fee/allowance/overage for credits or legacy billing.

`projectScenario` computes, from the model row the user has selected (falling back to the recommended row, then the first comparable row, with the fallback noted): usage = requests × the row's displayed cost (never recomputed); the allowance as `[base, base + flex]`; overage units conservatively per end (`low = max(0, usageLow − allowanceHigh)`, `high = max(0, usageHigh − base)`, so the pessimistic high-end overage can be nonzero even while the boundary reads within-flex, since flex is documented as variable); overage in USD only when the plan documents a rate; and a total that adds the fee exactly once and is `null` when the fee is undocumented (the legacy plan) rather than invented. Every quantity is rounded to 1e-6 before a boundary comparison. Every field carries typed provenance (`provider` with the registry date and sources, `user`, `history` with its window, or `estimate` with the cost basis). `plansFor`/`projectScenario`/`historyScenarioPrefill`/`scenarioDelta` all take injectable registries/dates for tests; production callers always use the exported defaults.

`Options.scenario` (`ScenarioSettings`, parsed tolerantly per field by `parseScenario` so a corrupted scenario never resets the rest of saved options) is part of `Workload`, so it saves and applies with profiles like every other workload setting. `optionResult` in `src/comparison.ts` projects each comparison side's own scenario from its own row/options; `comparisonDelta` adds a separate `scenario` delta (range-end difference, only for two `projected` results with the same unit and a non-null total) independent of the selected-row cost delta. `src/extension.ts` exposes `ViewState.planRegistryDate`, `ViewState.scenario` (the single view's projection), and `ViewState.scenarioPrefill` (`historyScenarioPrefill(usage)`, a request-range suggestion from local history's active/calendar days, applied client-side like **Use my average** — no new host message). `src/export.ts`'s `scenarioExport` labels the projection "estimated ... projection, not a bill" in the single-view snapshot (additive, still v3) and the pair snapshot/CSV assumptions (v3).

The webview's **Monthly spending scenario** card (`webview/main.ts` `renderScenario`) rebuilds the plan `<select>` from `plansFor` on every render (options can change with billing without a revision bump; an unknown saved plan id is kept as a disabled option, never dropped or swapped), while the selected value is tracked in a JS draft (`scenarioPlanDraft`) so a live selection survives an unrelated render before it round-trips — the same pattern `budgetDraft`/`byokDraft` use. The plan select and Custom fields send on the debounced options path with the other inputs; **Use my request history** stages `origin:"history"` immediately and sends. `freeBar` (`src/compare.ts`, pure) ranks free-tier models by benchmark score for the intelligence bar: same baseline as `freeSpotlight` (checklist exclusions and the text filter apply; `freeOnly`/`onlyMine` are ignored) but billing-independent, since free-tier costs are zero and the bar carries no cost unit — only a score is required, never invented, and paid/unscored rows are excluded. Sorted by score descending, then cost ascending (unpriced last), then name; empty for non-OpenCode sources. `src/extension.ts` threads it into `ViewState.freeBar` (`FreeBarEntry` in `src/types.ts`); the webview (`#free-bar-wrap` in the Tool analysis chart-card) draws a second Chart.js horizontal bar under the Pareto scatter (OpenCode-only, hidden otherwise), with click-to-select through the existing `select` message, a screen-reader list of the same values, and dynamic canvas height. PNG export still captures only the main chart, noted in the hint.

The custom comparison tray is webview-only: no new host message, storage, or export surface. The results table gains a `Pick` checkbox column plus a pick toggle in model details; `customPicks` (capped at 6) lives in module state persisted via `vscode.setState` alongside the last tab (tolerantly restored, never trusted from the host). `#custom-card` below the table renders the picked rows' scores and native costs on the current task/basis with its own score bar; a pick that leaves the view stays listed as no-longer-in-view until removed, never silently swapped. Coverage: `test/roadmap.test.ts` (`freeBar` ranking/baseline/tiebreak/billing-independence, new markup ids), `test/webview.spec.ts` (OpenCode bar visibility/order/aria, tray pick/stale/clear; bare `canvas` selectors now target `#chart`).

`sensitivity.ts` (pure, webview-safe: imports only `types` plus `recommend`, which is itself types-only) powers the workload sensitivity card with zero host surface: `mixCost` reprices a row at any token mix from its breakdown rates (buckets disjoint, write falls back to input like `estimate`; legacy rows without a breakdown stay constant, unpriced/unscored rows yield null), `frontierIds` repeats the `markFrontier` dominance rule, and `sweepMix`/`compressBreakpoints` sweep output share 0–100% at a fixed total (current input + output, or an illustrative 2,000-token fallback labelled as such) into breakpoint ranges with constant frontier + recommendation sets. The sweep holds the current context tier and skips context-limit exclusion as documented what-if approximations; legacy billing yields one flat range with an insensitive-to-mix note; single view only, nothing exported. The webview (`#sensitivity-card` below the custom tray) renders the ranges with an explicit not-measured-cost disclaimer and an empty note under two comparable rows. Coverage: `test/roadmap.test.ts` (bucket/write-fallback/legacy-constant/null cases, `frontierIds` parity with `markFrontier`, mid-sweep parity with `compare()`, recommendation flip, compression, new markup ids) and `test/webview.spec.ts` (ranges render, recompute on token edits, empty on filter-out).

`src/watchlist.ts` (pure) detects pinned-model changes between two renders for opt-in refresh notifications: per pinned row id it diffs price (finite costs), score (finite scores with `|delta| >= noiseThreshold`, so noise and null transitions stay silent), and mapping status; rows missing on either side are skipped so excluded rows never alert. Availability is stateless and source-scoped — a same-source pin (namespaced ids, bare ids default to Copilot) that is no longer discovered reads as no-longer-available, while cross-source pins, excluded pins, and empty pin lists stay silent, as does everything when no rows are comparable. `summarizeWatchChanges` formats one line per change citing both snapshot versions and retrieval dates. `src/extension.ts` keeps a `watchlistAlerts` global-state flag (default off, never per-option), serves it as `ViewState.watchlistAlerts`, handles a validated `watchlistAlerts` message (the webview sends it unwrapped so it never switches the comparison Editing side), and after a successful refresh with a new `fetchedAt` recomputes prev/curr rows with current availability and options before firing one non-modal `showInformationMessage` with an Open-comparison action. Coverage: `test/roadmap.test.ts` (each kind, noise/null/excluded/foreign/empty silence, summary versions), `test/extension.test.ts` (toggle persists and surfaces, notification fires only when opted in with a new snapshot and real changes, opt-out and unchanged snapshots silent — via a fetch stubbed before activate since `BenchmarkService` captures fetch at construction), and `test/webview.spec.ts` (Settings checkbox posts the toggle).
