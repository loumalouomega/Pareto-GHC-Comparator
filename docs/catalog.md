# Maintaining the catalog

Update `src/catalog.ts` against the two GitHub sources, change `catalogDate`, and verify rates, thresholds, promotional expiry dates, and legacy plan availability. Rates are USD per million tokens; `null` cache-write rates mean normal input billing. Add only explicit Copilot IDs. Do not infer a pricing mapping from a similar family or display name.

Update `src/staticSources.ts` against the provider pricing pages in `staticPricingSources`, keep `staticRegistryDate` current, and verify rates, units, context limits, IDs, benchmark aliases, and the `family` grouping used by the Family → Model → Thinking checklist. Preserve existing identities where valid so saved exclusions survive; never conflate distinct models in one alias (e.g. Gemini 3 Flash versus 3.5 Flash). Remove models the official docs mark retired, deprecated, or end-of-support instead of keeping stale rows. Static registries are illustrative API-equivalent USD estimates, not account availability or subscription billing.

Each model's optional `invocableId` — what **Copy** puts on the clipboard, via `src/invocable.ts` — must come from that client's own documentation listed in `staticInvocableSources`, never guessed from the display name or the registry key next to it on the same entry. Leave it unset when the client's docs don't confirm an exact id for that model (see `docs/model-switching-investigation.md` for the per-client evidence and known gaps, e.g. an open Gemini CLI bug that silently reroutes some `-flash` ids).

`benchmarkFamilies` contains explicit model-family aliases. Matching allows a known family name followed by a reasoning qualifier; it does not fuzzy-match sibling model names. A single candidate resolves automatically; multiple candidates expand automatically into one comparable row per variant, each with its own thinking-level checkbox. A model reporting its own thinking level resolves to that same level. The benchmark dropdown collapses a model back to one manual choice, and **Use automatic matching** restores the expansion. Preserve reasoning and fallback qualifiers. API response validation and the three index mappings live in `src/api.ts`; comparison and cost rules live in `src/compare.ts`. Keep new cases covered by tests, then build and package a new release. Full benchmark datasets are fetched using each user's key and are not bundled in the VSIX; the illustrated preview contains only its displayed scores.

`src/assist.ts` (pure, no aliases involved) adds a second, independent way to spot an unresolved mapping: an unverified suggestion when a benchmark's `slug` exactly equals the model's own identifier (lowercased, `.` → `-`, optionally followed by reasoning-suffix segments). It never widens matching for `resolveBenchmark`, never sets `mappingStatus`, and is shown to the user for explicit review; applying it just calls the normal mapping flow. The same module's `providerRegistries` table (currently `{ openai: "codex" }`) drives same-identifier BYOK pricing suggestions for OpenCode — add an entry only after verifying the registry publishes that provider's own API list prices (checked against `staticPricingSources`), never on name similarity.

`src/plans.ts` holds a dated, sourced plan registry (`planRegistry`, `planRegistryDate`, `planSources`) for the monthly spending scenario. Update it against the GitHub Copilot plan/billing docs and the OpenCode Go docs linked in `planSources`, and bump `planRegistryDate`. Keep `monthlyFeeUsd`/`flexAllowance`/`overageUsdPerUnit` `null` for anything not documented (never invent a figure — see the legacy annual plan's undocumented fee); a plan whose rules stop being verifiable moves to `unavailablePlan(...)` with a reason rather than being approximated from another plan. `plansFor`/`projectScenario` are pure and take an injectable `registry`/`registryDate` for tests; production code always uses the exported defaults. Preserve existing plan `id`s so saved scenarios and profiles keep resolving to the same plan after an update.
